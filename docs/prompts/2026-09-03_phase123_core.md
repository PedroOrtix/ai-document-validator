## Deliverable 1 — Domain models (`src/docvalidator/domain/`)

`models.py` with Pydantic v2 models:

- `ExtractedField`: `value: str | float | date | None` (use a sensible union; dates as `datetime.date`), `confidence: float` in [0,1], `evidence: str | None` (short quote from source), `page_hint: int | None`
- `DocumentExtraction`: `document_type: Literal["SUPPLIER_INVOICE"]`, `fields: dict[str, ExtractedField]` with keys exactly: `supplier_name, invoice_number, invoice_date, total_amount, currency, tax_id`; `metadata: ExtractionMetadata` (backend name, duration_ms, model/provider optional)
- `RuleResult`: `rule_id: str`, `passed: bool`, `message: str`
- `Verdict`: `status: Literal["PASS","FAIL","REVIEW"]`, `rule_results: list[RuleResult]`, `extraction: DocumentExtraction`
- `ValidationConfig`: `document_type: Literal["SUPPLIER_INVOICE"] = "SUPPLIER_INVOICE"`, `max_age_days: int = 90`, `allowed_currencies: list[str] | None = None`, `required_fields: list[str] = ["supplier_name","invoice_number","invoice_date","total_amount"]` — with validation (max_age_days > 0, currency codes 3 uppercase letters)

Confidence semantics (document in docstrings): 0.95+ exact labeled pattern (e.g. "Invoice No: X"), 0.7-0.9 strong structural pattern, <0.5 fuzzy/heuristic guess. Missing field => ExtractedField with value None and confidence 0.

## Deliverable 2 — Offline extractor (`src/docvalidator/extraction/`)

`base.py`: abstract `Extractor` protocol/ABC: `extract(document: DocumentInput) -> DocumentExtraction`.
`input.py`: `DocumentInput` model — either `text: str` (plain text) or `pdf_bytes: bytes`, plus optional `filename`. Include a helper `to_text()` that extracts text from PDF via pypdf (all pages joined); if PDF has no text layer, raise a typed `ExtractionError` (fail loudly, no silent empty results).

`offline.py`: `OfflineExtractor(Extractor)` — deterministic regex/heuristic extraction from text:
- invoice_number: labeled patterns (`Invoice No`, `Invoice #`, `Invoice Number`, `Factura Nº`...) with fallback to a bare `INV-YYYY-NNNN`-style pattern
- invoice_date: parse common formats (2025-01-31, 31/01/2025, 31 January 2025, Jan 31, 2025); validate real dates; labeled (`Invoice Date`, `Date`, `Fecha`) preferred
- total_amount: labeled (`Total`, `Total Amount`, `Amount Due`, `Grand Total`, `Total Due`) — prefer labeled "total" over bare numbers; handle `1.234,56 €` (European) and `1,234.56` (US) and currency symbols/codes nearby; store as float, never string
- currency: ISO-4217 codes (EUR, USD, GBP, ...) near the amount or a `Currency:` label; symbol mapping (€->EUR, £->GBP, $->USD) only when no explicit code
- supplier_name: first non-empty line heuristic, or `From:`/`Supplier:`/`Issued by:` label; strip legal suffixes? NO — keep the raw value, only trim whitespace
- tax_id: patterns VAT/TAX/USt-IdNr/NIF/CIF/NIE + country prefixes (DE123456789, ESX1234567X, GB123456789)

Each field records the matched text as `evidence` and a confidence per the semantics above. Unknown/unmatched => value None, confidence 0, no exception (missing fields are business outcomes, not errors; only unreadable input raises).

## Deliverable 3 — Rules engine (`src/docvalidator/rules_engine/`)

`base.py`: `Rule` protocol: `rule_id: str`, `evaluate(extraction, config) -> RuleResult`. A `RuleRegistry` (dict-based registration + `register` decorator) so new rules plug in without touching existing code.
`rules.py`: register these:
- `invoice_date_present_and_fresh` — FAIL if date missing (see aggregation below) or older than `config.max_age_days` from "today" (accept a `today: date` injection param for testability, default `date.today()`)
- `total_amount_present_and_positive` — FAIL if amount missing or <= 0
- `supplier_name_present` — FAIL if missing/blank
- `currency_allowed` — only evaluates when `config.allowed_currencies` is set: FAIL if currency missing or not in list; SKIP (passed=True, message "not configured") when unset
`engine.py`: `RulesEngine.evaluate(extraction, config) -> Verdict`:
- For each field in `config.required_fields` that is missing (value None): emit a synthetic RuleResult (`rule_id: "required_field_present"`, passed False, message naming the field), status contribution => REVIEW
- Run registered rules. Aggregation: any rule FAIL => overall FAIL; no FAIL but >=1 missing required field => REVIEW; else PASS
- REVIEW means "cannot judge, data missing"; FAIL means "judged and rejected". Document this in docstrings.
