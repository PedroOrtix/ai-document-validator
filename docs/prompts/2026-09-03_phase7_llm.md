## Deliverable — `src/docvalidator/extraction/llm.py`

`LLMExtractor(Extractor)` using httpx (already a dependency) against an OpenAI-compatible
chat-completions API (OpenRouter):

- Config via pydantic-settings (`src/docvalidator/settings.py` if absent, else extend api config):
  `OPENROUTER_API_KEY` (may be empty), `OPENROUTER_BASE_URL` (default https://openrouter.ai/api/v1),
  `VALIDATOR_LLM_MODEL` (default z-ai/glm-5.3-flash), `VALIDATOR_LLM_TIMEOUT_SECONDS` (default 30)
- System prompt (constant in the file, single source of truth): instruct the model to return ONLY
  strict JSON with the six fields, null for absent ones, ISO dates, float amounts, ISO-4217 codes;
  include a 1-line example. Keep it short (~20 lines) — paste it verbatim into the report.
- Output parsing: json.loads with one retry that strips markdown fences if the first parse fails;
  on invalid output raise a typed `ExtractionError` (no silent fallback to offline)
- Per-field confidence from the LLM path: fixed 0.75 (documented: model-reported confidence is
  not calibrated, so we don't pretend precision), evidence = the raw JSON response snippet per field
- Metadata: backend "llm", model id, provider "openrouter", duration_ms measured around the call,
  and token usage from the API response (`usage.total_tokens`) if present
- If `OPENROUTER_API_KEY` is empty → raise `ExtractionError` at construction or call time with a
  clear message (API layer maps it to 503 with hint "configure OPENROUTER_API_KEY or use the offline backend")
- API integration: in the backend-selection factory, "llm" now constructs LLMExtractor; map
  ExtractionError from LLM auth/config to HTTP 503, from parsing to HTTP 502; timeouts → 504
